## 1. 인터럽트 (Interrupt)

### 💡 개념
컴퓨터가 프로그램을 실행하는 도중에 특별히 처리해야 할 긴급한 상황(예외, 이벤트 등)이 발생했을 때, **현재 작업을 잠시 멈추고 긴급 상황을 먼저 처리한 뒤 원래 작업으로 돌아오는 기능**입니다.

> 🎧 **비유:** 공부(메인 작업)를 하고 있는데 전화벨(인터럽트)이 울려서 전화를 받고(인터럽트 처리), 다시 공부로 돌아오는 것과 같습니다.

### ❓ 인터럽트가 필요한 이유
- **폴링(Polling)의 한계 극복:** 인터럽트가 없다면 CPU는 키보드가 눌렸는지, 마우스가 움직였는지, 프린터 인쇄가 끝났는지 등을 계속해서 직접 확인(Polling)해야 하므로 CPU 성능이 심각하게 낭비됩니다.
- **CPU 효율성 향상:** 인터럽트를 사용하면 CPU는 평소에 다른 작업을 하다가 이벤트가 발생했을 때만 신호를 받아 처리하므로 자원을 매우 효율적으로 사용할 수 있습니다.

### ⚙️ 인터럽트의 주요 종류
- **하드웨어 인터럽트:** 마우스, 키보드, 하드디스크, 프린터 등 외부 장치(Hardware)가 CPU에게 신호를 보낼 때 발생합니다.
- **소프트웨어 인터럽트 (예외/트랩):** 프로그램 실행 중 오류가 발생했거나(예: 0으로 나누기, 메모리 접근 오류), 운영체제의 도움이 필요할 때(시스템 콜) 발생합니다.

### 🔄 인터럽트 처리 과정
```text
[1. 인터럽트 요청] ➔ [2. 현재 상태 저장(Context Saving)] ➔ [3. ISR 실행] ➔ [4. 복구 및 재개]
```
1. **인터럽트 요청:** 장치나 프로그램이 CPU에게 신호를 보냅니다.
2. **현재 상태 저장 (Context Saving):** CPU는 실행 중이던 작업의 상태(레지스터 값 등)를 백업합니다.
3. **인터럽트 서비스 루틴 (ISR) 실행:** 해당 인터럽트를 처리하기 위해 미리 지정된 전용 프로그램 코드를 실행합니다.
4. **복구 및 재개:** 처리가 끝나면 백업해 둔 이전 상태를 불러와 멈췄던 원래 작업으로 돌아가 이어서 진행합니다.

## 2. 라이브러리 (Library)

### 💡 개념
프로그래밍에서 라이브러리란 **"다른 사람들이 미리 만들어 둔 유용한 기능, 함수, 클래스들의 모음집"**입니다.

> 🛠️ **비유:** 의자를 만들 때 나사나 망치를 처음부터 직접 깎아 만드는 대신, 철물점에서 규격화된 부품을 사서 조립하는 것과 같습니다.

### 🎯 라이브러리의 장점
- **시간 절약:** 입출력, 복잡한 수학 연산, 파일 입출력 등을 매번 직접 구현할 필요가 없어 개발 속도가 향상됩니다.
- **안정성 검증:** 이미 수많은 사용자에게 검증된 코드이므로 버그가 적고 안전합니다.
- **코드의 간결화:** 코드의 양이 줄어들어 유지보수가 용이해집니다.

### ⚔️ 라이브러리 vs 프레임워크
| 구분 | 라이브러리 (Library) | 프레임워크 (Framework) |
| :--- | :--- | :--- |
| **주도권** | 개발자에게 있음 (필요할 때 가져다 씀) | 프레임워크에 있음 (정해진 틀에 코드를 맞춤) |
| **비유** | 요리할 때 필요한 도구를 꺼내 쓰는 것 | 완성된 주방에서 지정된 레시피 순서대로 요리하는 것 |

## 3. 동적 링크 라이브러리 (DLL)

### 💡 개념
DLL(Dynamic-Link Library)은 윈도우(Windows) 운영체제에서 **여러 프로그램이 기능(코드, 데이터 등)을 공유해서 사용할 수 있도록 만든 외부 파일 형태의 라이브러리**입니다. (확장자: `.dll`)

> 🧰 **비유:** 여러 가구에서 각각 도구를 사서 쌓아두는 대신, 아파트 단지 내에 '공용 공구함(DLL)'을 하나만 두고 필요할 때마다 빌려 쓰는 것과 같습니다.

### ✨ DLL의 장점
- **메모리 및 용량 절약:** 여러 프로그램이 동일한 공용 DLL 파일을 공유하여 사용하므로 RAM과 하드디스크 용량을 아낄 수 있습니다.
- **유지보수 및 업데이트 용이:** 특정 기능에 버그가 발생한 경우, 프로그램 전체를 다시 설치할 필요 없이 해당 DLL 파일만 교체하면 됩니다.
- **개발 생산성 증가:** 마이크로소프트나 제3자가 제공하는 표준 DLL을 활용하여 개발 속도를 높일 수 있습니다.

### ⚠️ 자주 발생하는 DLL 오류
> *"msvcp120.dll이 없어 프로그램을 시작할 수 없습니다."*
- **원인:** 해당 프로그램 실행에 필수적인 공용 라이브러리(DLL) 파일이 시스템에 없거나 손상되었을 때 발생합니다.
- **해결책:** 해당 라이브러리 패키지(예: `Visual C++ 재배포 가능 패키지`)를 재설치합니다.

## 4. 정적 라이브러리 vs 동적 라이브러리

정적 라이브러리는 프로그램에 필요 코드를 아예 복사해서 붙여넣는 방식이며, 동적 라이브러리는 프로그램 실행 시점에 위치만 참조하여 연결하는 방식입니다.

### 📊 상세 비교 표

| 비교 항목 | 정적 라이브러리 (`.lib` / `.a`) | 동적 라이브러리 (`.dll` / `.so`) |
| :--- | :--- | :--- |
| **결합 시점** | 빌드(컴파일)할 때 합쳐짐 | 프로그램이 실행될 때(런타임) 연결됨 |
| **파일 크기** | 라이브러리 코드가 포함되어 실행 파일(`.exe`)이 큼 | 코드 내용이 빠져있어 실행 파일 크기가 작음 |
| **메모리 사용** | 프로그램마다 메모리에 각각 따로 적재됨 (낭비 발생) | 여러 프로그램이 하나의 DLL을 메모리에서 공유 (효율적) |
| **업데이트** | 수정 시 프로그램 전체를 다시 빌드 및 재배포 필요 | 수정된 DLL 파일만 교체하면 완료됨 |
| **독립성** | 단독 실행 가능 (의존성 없음) | 실행 시 반드시 해당 DLL 파일이 존재해야 함 |

## 5. 어셈블리 조건부 처리 (Conditional Processing)

어셈블리 언어에서는 플래그(Flags) 상태와 조건부 점프(Conditional Jumps) 명령어를 활용하여 C/C++ 언어의 `if`, `while`, `switch` 문 등을 구현합니다.

### 5.1 조건부 제어 구조 (IF / IF-ELSE)

#### 🔹 `if (op1 == op2)` 구문 구현
비교 명령어 `cmp`와 조건부 점프 `jne`(Jump if Not Equal)를 조합하여 조건문의 블록을 스킵하는 방식으로 작성합니다.

```assembly
; C++: if (op1 == op2) { X = 1; Y = 2; }
    mov eax, op1
    cmp eax, op2       ; op1 == op2 비교
    jne L1             ; 다르면 L1으로 점프 (조건 거짓일 때 스킵)
    mov X, 1           ; 참일 때 실행
    mov Y, 2
L1:
```

#### 🔹 `if-else` 구문 구현
조건이 거짓일 때 실행 흐름을 분기하기 위해 `jmp`를 함께 활용합니다.

```assembly
; C++: if (op1 > op2) call Routine1; else call Routine2;
    mov eax, op1
    cmp eax, op2
    jg  A1             ; op1 > op2이면 A1으로 이동
    call Routine2      ; 거짓(else)인 경우 실행
    jmp A2             ; else 실행 후 exit
A1:
    call Routine1      ; 참인 경우 실행
A2:
```

### 5.2 논리 연산자 및 복합 조건식

#### 🔹 Logical AND (`&&`)
두 조건이 모두 참이어야 실행됩니다. 하나라도 거짓이면 즉시 전체 구문을 스킵하는 **Short-Circuit Evaluation** 기법을 적용합니다.

```assembly
; C++: if (al > bl && bl > cl) X = 1;
    cmp al, bl
    jbe Next           ; 첫 번째 조건이 거짓(<=)이면 즉시 탈출
    cmp bl, cl
    jbe Next           ; 두 번째 조건이 거짓(<=)이면 즉시 탈출
    mov X, 1           ; 둘 다 참일 때만 실행
Next:
```

#### 🔹 Logical OR (`||`)
조건 중 하나라도 참이면 참 블록으로 점프합니다.

```assembly
; C++: if (al > bl || bl > cl) X = 1;
    cmp al, bl
    ja  L1             ; 첫 번째 조건이 참(>)이면 바로 L1으로 점프
    cmp bl, cl
    jbe Next           ; 두 번째 조건마저 거짓이면 탈출
L1:
    mov X, 1           ; 참일 때 실행
Next:
```

### 5.3 조건부 루프 (WHILE / REPEAT)

#### 🔹 `while` 루프 구현
루프의 시작 부분에서 조건을 검사하고 거짓이면 루프를 종료합니다.

```assembly
; C++: while (val1 < val2) { val1++; val2--; }
    mov eax, val1
BeginWhile:
    cmp eax, val2
    jnl EndWhile       ; val1 < val2가 아니면(>=) 루프 종료
    inc eax            ; val1++
    dec val2           ; val2--
    jmp BeginWhile     ; 루프 반복
EndWhile:
    mov val1, eax      ; 최종 값 저장
```

#### 🔹 플래그 보호 (`pushfd` / `popfd`)
루프 연산 중 플래그 값이 변경되는 것을 방지하기 위해 `pushfd`로 플래그 상태를 백업하고 `popfd`로 복원하여 조건부 루프(`loope`, `loopnz`)가 올바르게 작동하도록 돕습니다.

```assembly
L1:
    cmp WORD PTR [esi], 0
    pushfd             ; test/cmp 직후 플래그 상태를 스택에 백업
    add esi, TYPE array; 주소 이동 (플래그가 변경됨)
    popfd              ; 스택에서 원래 플래그 복원
    loope L1           ; 백업 복원된 플래그를 기준으로 루프 판단
```

### 5.4 테이블 기반 선택 (Table-Driven Selection)

다중 `switch-case` 문을 효율적으로 처리하기 위해 **값과 함수 포인터(Offset)의 쌍으로 구성된 테이블**을 이용한 간접 호출 방식입니다.

```assembly
.data
CaseTable BYTE 'A'
          DWORD Process_A   ; 매칭 값 'A'와 실행할 함수 주소
          BYTE 'B'
          DWORD Process_B
          BYTE 'C'
          DWORD Process_C
NumberOfEntries = 3

.code
    mov ebx, OFFSET CaseTable
    mov ecx, NumberOfEntries
L1:
    cmp al, [ebx]          ; 입력값 AL과 테이블 값 비교
    jne L2                 ; 불일치 시 다음 엔트리로
    call NEAR PTR [ebx+1]  ; 일치 시 해당 프로시저 간접 호출
    jmp L3
L2:
    add ebx, 5             ; 다음 엔트리 위치로 이동 (1 byte + 4 bytes)
    loop L1
L3:
```

### 5.5 고급 조건부 제어 지시어 (.IF / .WHILE)

MASM 어셈블러는 C 언어 스타일의 조건문 작성을 지원하는 매크로 지시어를 제공하며, 컴파일 시 적절한 `cmp` 및 조건부 점프 코드로 자동 변환됩니다.

```assembly
; 지시어 사용 코드
mov eax, 6
.IF eax > val1
    mov result, 1
.ELSE
    mov result, 0
.ENDIF

; 반복문 지시어 예시
.REPEAT
    inc eax
.UNTIL eax == 10

.WHILE eax < 10
    inc eax
.ENDW
```
